# Fresh lab bootstrap

This acceptance run creates new application, identity and VPN state on isolated
Debian 12 VMs. Clean-host restore is a separate
[recovery procedure](clean-host-recovery.md).

## Freeze before rebuilding

- Preserve an authenticated encrypted recovery point on the controller before
  rebuilding HOU4. Keep its decryption identity off both VMs.
- Record both infrastructure commits, the CI image receipt/source bundle,
  private inventory inputs, encrypted capabilities and issued certificate seeds.
- Bind each VM to its hostname, LAN address, NIC and verified SSH key. Verify
  independent provider-console or guest-agent access.
- Provision a working guest agent or serial console before application bootstrap;
  use that path to verify the new SSH key after replacing each OS disk.
- Keep current controller peer state and instance-bound API ciphertext for
  rollback. Use a new encrypted token path for the fresh control plane.

VM disks, hardware and provider firewall rules belong to the provisioning
project. Preserve those declarations during the OS rebuild. Host SSH keys,
VPN peer IDs and the receiver transport key are generated outputs; verify and
record their bindings before the next phase uses them.

## Bootstrap order

Use private bootstrap inventories generated by `scripts/prepare-lab.py`, selected
tooling/collections and the controller age identity. Execute initial commands
through [bootstrap transport](../deployment-workflow.md#isolated-controller-transport).
Run each playbook in full, with the selected inventory alias and declared inputs.

1. HOU1: `rehearsal-prepare.yml`, then `lab-dns.yml`. Preparation waits for provider
   initialization and starts opted-in lab DNS before installing Docker with its
   declared DNS consumers. The DNS entry point then verifies the complete setup.
2. HOU1: `rehearsal-seeds.yml`, then `rehearse-vps.yml`. Seed only host-encrypted
   certificates/geolocation files. The selected release supplies the application;
   identity/VPN roles create fresh state and persist the new API credential.
3. Enroll the dedicated test controller peer. Derive its access CIDR from the
   enrollment receipt and bind the managed transport to its verified address.
4. HOU1: run `hou1.yml` over the new VPN path. Verify fresh private SSH before
   retiring bootstrap access.
   If internal test passwords are required, explicitly run
   `rehearsal-identities.yml` with `authentik_test_seed_source` pointing to scoped
   SOPS ciphertext. Its `TEST_IDENTITIES` list contains username/password records
   for a subset of `authentik_staff_users`. It changes existing non-superusers'
   passwords only when needed; it does not create users or change access grants.
5. Rebuild HOU4. Run its `rehearsal-prepare.yml`, `lab-dns.yml` and `hou4.yml`
   through the enrolled controller transport. HOU4 preparation establishes the
   resolver stub only on an unconfigured test host.
6. Pair backups using the HOU4-generated public transport key and HOU1's public
   `backups.yml`. Keep both sides enabled in the managed inputs; capture, collect
   and verify a fresh encrypted point.
7. Verify the generated inventories' managed handoff, then reconcile and repeat
   through `scripts/deploy-lab.py`. Require stable container IDs on unchanged
   inputs and a clean application checkout.

## Acceptance records

Retain input hashes, generated identity bindings and every failed attempt.
Changes after a failure belong to a continued-host result; an uninterrupted
fresh-host claim requires a clean attempt from its declared inputs.

Run standalone readiness verification, the maintained failure matrix and explicit
reboot observers. Record backup decryption/integrity separately from a live
database or identity-service restore.

Scheduled capture briefly stops VPN writers. The managed workflow and failure
matrix now share its host lock; upgrade an established source through `backups.yml`
before concurrent acceptance. Direct commands remain outside that admission path.
The [rebuild evidence](../evidence/lab-bootstrap-2026-11-19.md) preserves the earlier
collision; [coordination acceptance](../evidence/capture-coordination-2026-11-19.md)
records the corrected overlap and controller-loss checks.
